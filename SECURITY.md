# Security Policy

## Knowledge Without Borders

Security and privacy are fundamental principles of Knowledge Without Borders.

The application is designed around a local-first architecture, keeping users' knowledge libraries and research data under their control.

## 1. Supported Versions

Security fixes will primarily target the latest maintained version of Knowledge Without Borders.

Older versions may not receive security updates.

## 2. Reporting a Vulnerability

Please do not publicly disclose security vulnerabilities before they have been reviewed and addressed.

Use GitHub's Private Vulnerability Reporting feature when it is enabled for this repository.

Until that feature is available, contact the repository owner privately through GitHub.

## 3. Information to Include

A vulnerability report should include:

- A clear description of the issue.
- Steps to reproduce it.
- The affected application version.
- The affected operating system.
- Potential security or privacy impact.
- Relevant screenshots or logs, with sensitive information removed.

## 4. Protecting User Data

Never include the following in public Issues, Pull Requests, or repository commits:

- Personal knowledge databases.
- Private KWB export files.
- Personal research notes.
- API keys or access tokens.
- Passwords and credentials.
- Private attachments or personal documents.

## 5. Security Principles

The project aims to maintain:

- Local ownership of user data.
- Safe import and export operations.
- Validation of exchanged knowledge packages.
- Protection of application credentials.
- Secure handling of external translation services.
- Transparent handling of network connections.

## 6. Responsible Disclosure

We appreciate security researchers and contributors who help identify vulnerabilities responsibly.

Thank you for helping protect Knowledge Without Borders and its users.
